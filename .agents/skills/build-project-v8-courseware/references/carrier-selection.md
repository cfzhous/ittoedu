# 场景所有权与状态选择

先选择谁拥有整体场景，再选具体 API。

| 所有权 | 使用条件 | 主要风险 |
| --- | --- | --- |
| `native-owned` | 简单图文、公式、图片、稳定排版、逐步显现和少量规则 | 为复杂行为堆积状态/规则 |
| `runtime-owned` | 一次性高定制构图、连续拖动、算法、参数联动、SVG/Canvas/WebGL/Three，或原生化导致状态爆炸 | 内容变黑箱、静态后备缺失 |
| `hybrid-owned` | Runtime 负责复杂视觉/行为，原生节点或少量状态负责稳定内容、检查点或办公格式映射 | 两套结果重复执行 |
| `component-composed` | 已有可信目录组件，或机制跨场景/课例复用且 Props、版本与生命周期边界稳定 | 一次性效果被过早抽象 |

选择质量更高、机制更薄且仍满足必要编辑性的最短充分方案。不要用“代码复杂”“视觉重要”或“以后可能复用”证明组件化。

Presentation State 只用于初始、错误、成功、总结、缩略图、静态输出帧或教师跳转点。悬停、拖动轨迹、补间帧、高频参数和临时粒子留在 Runtime。

出现下列信号时把规则/状态收回 Runtime：规则相互等待、临时布尔量扩散、为连续过程枚举大量状态、同一行为同时存在源码与规则、或状态只为实现而无教学/复核意义。
