## 1. 背景与决策

本轮启动前，编辑器已经具备 Project V7、命名状态、声明式交互、自由运行时、组件、音视频、全局层和四种导出能力，但多个功能直接暴露了底层数据模型。以下内容是重构基线，不代表当前完成状态：

- “元素”和“素材”曾是重复入口，当前已有合并第一版，但内容仍以长列表和折叠区堆叠；
- 动画和规则编辑以参数表单为主，用户很难建立“何时触发、执行什么、先后关系如何”的完整心智模型；
- 简洁/专业模式已有开关，但主要差别仍是隐藏少量入口，没有形成不同工作流；
- 透明度含义与用户常识相反；
- 中文字体使用英文名称，缺少可用性提示；
- 竖排只有右起，自动高度又阻止竖排文本框纵向拉伸；
- 原生文字可以双击画布编辑，组件公开文字只能在属性栏中修改；
- 专业模式只能查看运行时摘要，不能对项目级运行时和可编辑组件做代码级修改；
- 单 HTML 和网页包仍携带完整 Project V7 及组件作者态信息，网页包还重复保存组件运行代码。

本轮不建设账号、服务器工程存储、MCP、Agent 沙箱、DRM、授权服务器或重型混淆。产品竞争力优先投入编辑效率、资产、课例和生成能力。

## 2. 总体目标

### 2.1 用户结果

简洁模式用户应能在不理解 Project Schema、规则 ID、运行时协议和组件包结构的情况下完成：

```text
新建/打开
  → 添加文字、图片、图形、视频或已有素材
  → 在画布和属性栏中修改
  → 设置常见出现动画
  → 局部试运行/整课预览
  → 工程检查
  → 导出
```

专业模式用户应能继续完成：

- 命名状态、全局层和完整规则编排；
- 音视频高级设置和组件包管理；
- 精确几何、批量操作与诊断；
- 场景/全局运行时代码修改；
- 选中对象 JSON 检查与受控修改；
- 对明确允许编辑的组件创建可编辑副本并修改代码。

### 2.2 非目标

- 不把编辑器改造成通用网页 IDE；
- 不建设关键帧、曲线路径或通用动画时间轴；
- 不自动反向解析任意组件 DOM/Canvas；
- 不保证浏览器运行代码不可逆向；
- 不改变 Project V7 作为工程业务真相的地位；
- 不因简洁模式而删除、关闭或降级专业内容；
- 不为网页端预先重写当前 Electron 外壳。

## 3. 不可破坏的架构约束

1. 简洁/专业模式是本地界面偏好，不进入 `.h5lesson`，切换模式不得产生工程历史记录。
2. 预览、单 HTML 和网页包继续使用同一 Player 运行语义。
3. 简洁动画和常用点击行为必须映射为标准 `InteractionRule`，不建立第二套规则模型。
4. 命名稳定状态继续由 `scene.presentation` 表达；动画只修改 Player 瞬态。
5. 原生文字、运行时 `content.values` 和组件 `props.content` 继续承担全部人工可见文字。
6. 旧 Project V1–V6、旧 `writingMode: "vertical"`、Runtime API 1 和 Component API 1–3 必须兼容。
7. PDF/PPTX 的静态语义不得因互动编辑器改造而变化。
8. 发布裁剪是 Project V7 到 PublishedLesson 的单向转换，成品不得作为工程重新导入。

### 4.1 简洁模式

顶部保留：

5. 更多设置。

简洁模式必须保留大部分图文编辑能力。精确坐标、运行时声明、全局可见范围、复杂规则和组件管理进入专业模式或折叠的“更多设置”。

### 4.2 专业模式

5. 开发。

专业模式额外开放：

- 状态管理；
- 完整规则；
- 组件包管理；
- 高级声音设置；
- 运行时与受控代码编辑；
- 工程检查与诊断定位。

### 4.3 统一“元素”

“元素”内部使用搜索框和分类，不再用多个一级 Tab 或一个无限增长的折叠长页：

- 常用：文本、图片、视频、声音和全部图形快捷入口；
- 媒体：只管理已进入工程的声音、视频、图片及专业声音设置，不重复放置快捷入口或导入按钮；
- 互动组件（专业）；
- 控制与全局（专业）。

同一素材只保留一个管理入口。已有图片/视频点击“添加到画布”时继续复用同一 Asset ID。

## 5. 里程碑1：基础文字与显示正确性

### 5.1 透明度

用户语义：

- 透明度 0%：完全不透明；
- 透明度 100%：完全透明。

内部数据继续使用不透明度：

```ts
transparencyPercent = (1 - opacity) * 100
opacity = 1 - transparencyPercent / 100
```

要求：

- 建立集中换算函数，禁止各面板自行计算；
- 元素透明度、文本背景、控制器背景等所有标为“透明度”的控件统一；
- 工程数据不迁移；
- 画布、Player、缩略图、PDF、PPTX 保持内部 `opacity` 语义。

验收：

- 输入 0、50、100 时，工程分别保存 1、0.5、0；
- 撤销/重做正确；
- 四种导出与编辑画布观感一致。

### 5.2 中文字体

字体条目至少包含：

- 微软雅黑 / Microsoft YaHei；
- 宋体 / SimSun；
- 黑体 / SimHei；
- 楷体 / KaiTi；
- 仿宋 / FangSong；
- 苹方 / PingFang SC；
- 冬青黑体 / Hiragino Sans GB；
- 思源黑体 / Source Han Sans SC；
- 思源宋体 / Source Han Serif SC；
- Noto Sans SC / Noto Serif SC；
- 常见西文字体和通用回退字体。

要求：

- 列表主标签使用中文名，副标签显示 CSS family；
- 使用 `document.fonts.check()` 标记“可用/未安装/无法检测”；
- 搜索同时匹配中文名、英文名和 family；
- 允许输入自定义 family 或回退字体串；
- 未安装字体不静默伪装为已生效；
- 本轮不内置大型中文字体文件。

后续字体文件导入属于增强项：只有授权清晰的 WOFF2/TTF/OTF 才能登记并随成品输出。

### 5.3 双向竖排与方向感知尺寸

新规范值：

```ts
type WritingMode = "horizontal" | "vertical-rl" | "vertical-lr"
```

兼容：

- 载入旧 `"vertical"` 时规范化为 `"vertical-rl"`；
- 新保存不再写 `"vertical"`；
- 旧工程视觉不得改变。

尺寸语义：

- 横排 `auto-height`：用户调整宽度，系统计算高度；
- 竖排 `auto-height` 的兼容输入规范化为方向感知自动尺寸：用户调整高度，系统计算宽度；
- 固定尺寸与缩小字体模式仍允许独立改变宽高；
- 竖排时上下手柄始终可以拉长文本框；
- 文字编辑浮层与画布选框使用实际渲染宽高。

验收矩阵：

- 横排、右起竖排、左起竖排；
- 自动尺寸、固定裁切、自动缩小；
- 中文标点、英文、数字、换行和局部样式；
- 编辑画布、缩略图、Player、PDF、PPTX。

## 6. 里程碑2：简洁/专业模式成为两套工作流

### 6.1 模式切换

- 默认简洁模式；
- 使用本地存储记忆；
- 切换时提交尚未结束的文字编辑；
- 从“互动与动画 / 开发”切回简洁模式时安全返回“属性”并提示高级内容仍保留；
- 简洁出现动画检测到重叠专业规则时显示“打开专业规则”；
- 不删除、不禁用专业内容。

### 6.2 简洁模式降负

- 常用操作前置，精确参数折叠；
- 顶部减少并列按钮；
- 工程检查在导出时自动运行，错误仍阻断；
- 全局声音高级混音只在专业模式显示；
- 组件导入、包替换和删除只在专业模式显示；
- 场景状态已有内容可查看，但创建、排序、初始/缩略图指定属于专业模式。

### 6.3 专业模式增强

- 不是简单显示更多字段，而是增加“互动与动画”和“开发”两条完整工作流；
- 保留精确坐标、状态覆盖、多选、全局层、组件和诊断；
- 专业模式直接显示最近工程、另存为、工程检查、组件导入和完整五个右栏入口。

验收：

- 同一工程在两种模式切换前后深度相等；
- 简洁模式能完成常用闭环；
- 专业内容在简洁模式仍正常预览和导出；
- 重新启动后恢复上次模式。

## 7. 里程碑3：互动与动画工作流重构

### 7.1 统一术语

用户界面统一使用“互动与动画”，不再使用“场景自动化”。

规则解释统一为：

```text
当（触发）
如果（可选条件）
就（一个或多个动作）
```

底层继续对应：

```ts
InteractionRule {
  trigger
  conditions
  actions
}
```

### 7.2 简洁模式

选中元素时提供：

1. 出现方式：无、淡入、滑入、缩放；
2. 滑入方向、快速/标准/舒缓速度和常用延迟；
3. 当前元素动画就地预览；
4. 检测到重叠专业入场规则时显示“打开专业规则”，切换专业模式并定位“互动与动画”。

简洁模式首版不另造“点击后”快捷模型。节点点击继续在专业“属性 / 交互”中使用标准 `node.click` 规则维护，避免同一规则再次出现在简洁属性和规则中心。

简洁规则必须：

- 使用稳定 ID；
- 与 `playbackInitialVisibility` 原子提交；
- 可一次撤销；
- 删除时清理关联的动画完成引用；
- 检测专业规则冲突，不静默覆盖。

### 7.3 专业规则中心

布局：

- 规则列表：搜索、作用域、触发器、目标元素、启用状态筛选；
- 规则摘要：自然语言概览；
- 规则编辑：当/如果/就三段；
- 动作序列：显示动作编号、顺序/同时、局部延迟和预计等待；
- 诊断：缺失引用、不可达事件、重复动画、终止动作位置错误；
- 预览：元素动画可就地预览，完整规则用当前位置试运行。

规则模板至少包括：

- 进入场景 → 元素依次出现；
- 声音结束 → 下一场景；
- 视频结束 → 下一场景；
- 组件完成事件 → 切换状态；
- 动画完成 → 下一场景。

模板只生成标准规则，不引入模板运行时。节点点击类常用行为仍由“属性 / 交互”维护，不在非点击规则中心重复提供模板。

### 7.4 去重

- 完整规则只在“互动与动画”编辑；
- 属性栏只显示与当前元素相关的规则摘要、常用点击动作和跳转入口；
- 同一条 `node.click` 不在两个完整编辑器中重复；
- 全局层使用同一规则中心，并增加生效场景条件。

验收：

- 旧规则全部可读可改；
- 新增、复制、启停、删除和排序保持可撤销；
- 顺序组、并行组和终止导航语义不变；
- Player 回归测试覆盖重复触发、取消和完成事件。

## 8. 里程碑4：专业开发能力与组件画布文字编辑

### 8.1 开发面板边界

专业“开发”面板允许修改项目承载的代码和结构，不暴露编辑器自身源码。

交互采用加宽的单任务工作台：“运行时 / 对象 JSON / 规则 JSON / 组件代码”四类任务通过标签切换并显示就绪状态，一次只呈现一类编辑内容；组件 Runtime 与 Manifest 再通过二级标签切换。代码区使用较大等宽字号、不自动折行，并占据剩余面板高度。

首版包括：

- 场景运行时源码；
- 全局运行时源码；
- 当前选择对象 JSON；
- 当前规则 JSON；
- 可编辑组件副本的 manifest 和 runtime；
- 格式化、校验、错误提示、撤销、重做和试运行。

不包括：

- 任意文件系统浏览；
- Node/Electron API；
- 远程依赖安装；
- 任意 Shell；
- 编辑器源码修改。

### 8.2 运行时代码编辑

- 只在专业模式显示；
- 源码修改进入正常工程历史；
- 保存前执行大小、禁止语法和同步注册校验；
- `renderMode` 改变不自动改写源码；
- 试运行仍在现有受限 Player 环境中执行；
- 错误可定位到场景/全局运行时。

### 8.3 组件代码编辑

- 默认第三方包只显示公开参数和只读 manifest/runtime；
- 用户对所选实例执行“创建可编辑副本”后才能修改工程内副本；
- 副本获得新包 ID/版本，避免覆盖原包；
- 修改后必须通过 manifest、运行时注册、作用域和素材引用校验；
- 只读只阻止直接覆盖，不隐藏源码；创建副本前由用户确认许可证允许修改和二次分发；
- 本轮不建设复杂许可证服务器。

### 8.4 组件画布文字编辑协议

不得根据 DOM 文本内容猜测 Props。组件必须显式登记可编辑区域。

DOM 组件约定：

```html
<span data-courseware-edit-key="content.title">标题</span>
```

Phaser/hybrid 组件约定：

```ts
ctx.editor?.registerTextRegion({
  key: "content.title",
  getBounds: () => ({ x, y, width, height })
})
```

宿主行为：

- 编辑状态双击登记区域；
- 根据 key 读取和写回组件实例 Props；
- 显示轻量文字编辑浮层；
- 支持中文输入法、提交、取消和撤销；
- 未登记区域仍把组件作为整体选择；
- 旧组件继续在属性栏修改，不报错、不降级。

`ctx.editor` 是仅 edit 模式可能存在的可选兼容桥，兼容上下文类型 V1–V4 都必须判空；preview/capture Player 不提供。登记 key 仍须映射到公开 `text` / `textarea` 字段或有效 `props.content` 字符串，V1 通常因此继续保持整体选择。该协议不提高 Component API 版本，也不是 V4 的运行必需能力。

验收：

- DOM 和 Phaser 示例组件各有一条画布内文字编辑路径；
- 全局组件与场景组件均可工作；
- 状态覆盖中的组件 Props 写入当前状态而非基础；
- 试运行模式不出现编辑命中区；
- 保存重开后文本保持。

## 9. 里程碑5：PublishedLesson 最小发布裁剪

### 9.1 发布边界

工程文件：

```text
Project V7
  = 作者态、可继续编辑、含完整组件包和运行时源码
```

成品文件：

```text
PublishedLesson V1
  = Player 执行态、不可重新导入为工程、只含运行必需数据
```

### 9.2 必须删除的作者态内容

- `createdAt`、`updatedAt`；
- `componentPackages`；
- 组件 `editor.properties`、pages、previewPageProp；
- variants、presets、description；
- 运行时内容字段的编辑标签与说明；
- 状态说明、调试摘要和编辑器导航元数据；
- 工程历史、恢复信息和本地路径；
- 原始组件包目录；
- 独立源码映射文件和重复源码副本。

PublishedLesson V1 为保证执行语义和任意 Unicode 代码单元完全一致，不改写 JavaScript 字符串本身；源码内已有注释、`sourceURL` 或其他可读标记仍可能随可逆编码保留。需要清理时应在组件/运行时构建阶段完成，发布裁剪不承诺替作者剥离。

### 9.3 必须保留的执行内容

- 画布尺寸和成品标题；
- 场景显示名称（场景目录需要）；
- 场景、状态、节点和层级；
- 声明式交互；
- 全局层和播放设置；
- 音视频定义；
- 运行所需素材；
- 运行时和组件的最小能力声明；
- 浏览器执行所需代码。

浏览器必须获得可执行代码，因此本里程碑不承诺“不可逆向”。目标是：

- 不直接复制原始组件包；
- 不把原始 `runtimeSource` 字段与独立 `runtime.js` 重复交付；
- 使用单一、压缩或编码的执行表示；
- 不携带作者态 manifest；
- 不携带完整 Project V7。

### 9.4 包结构

单 HTML：

```text
index.html
  ├─ Player bundle
  ├─ PublishedLesson V1
  ├─ 执行代码表示
  └─ 内联素材
```

网页包：

```text
index.html
course-data.js       # 唯一 PublishedLesson V1 发布数据，同时支持 HTTP 与 file://
player/
  ├─ player.iife.js
  └─ player.css
assets/...
component-assets/...
```

场景/全局运行时与组件执行字符串编码为 `base64-utf16le`，直接位于 `course-data.js` 的最小运行描述中；不再生成 `course.json`、离线回退数据或独立 `executables/`、组件 `runtime.js`。编码精确保留中文、Emoji 和 JavaScript UTF-16 代码单元，但可逆，不构成源码保密。

### 9.5 泄漏门禁

自动测试必须验证单 HTML 与网页包不存在：

- `"schemaVersion":7` 作为顶层工程；
- `createdAt` / `updatedAt`；
- `componentPackages`；
- `runtimeSource`；
- 组件 `editor` / `variants` / `presets`；
- `project.json`；
- 独立 `.map` 文件；
- 原始组件包路径和重复运行代码。

同时必须验证：

- 所有原生节点、状态、规则和媒体正常播放；
- Runtime API 1/2、Component API 1–4 兼容；
- 单 HTML 与网页包语义一致；
- CSP 和离线播放保持；
- PDF/PPTX 不受影响。

## 10. 迁移与兼容策略

### 10.1 WritingMode

- 载入阶段规范化旧值；
- 内存和新保存使用新值；
- 测试 V1–V7 迁移；
- 不提高 Project Schema 版本。

### 10.2 组件协议

- 画布文字登记是兼容上下文的 edit-only 可选扩展，不绑定 Component API 4；
- 未实现登记的 V1–V4 组件保持原行为；
- 不把编辑能力当作运行时必需字段。

### 10.3 发布格式

- `.h5lesson` 保存格式不变；
- 只有单 HTML 和网页包切换到 PublishedLesson；
- Player 在过渡期可同时接受旧 ExportPayload 和 PublishedLesson，稳定后内部预览也统一新格式；
- PublishedLesson 不注册为工程导入格式。

## 13. 风险与处理

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 竖排改动影响旧工程 | 视觉回归 | 旧 `vertical` 明确映射 `vertical-rl`，增加快照测试 |
| 自动尺寸规则复杂 | 拖拽跳变 | 把“用户可改轴”和“自动计算轴”写成单一函数 |
| 简洁规则与专业规则冲突 | 重复播放 | 写入前检测作用域、状态和目标元素 |
| 规则中心重构丢失能力 | 专业功能降级 | 保留原数据编辑覆盖矩阵并逐类测试 |
| 代码编辑破坏工程 | 无法预览 | 校验、撤销、试运行、错误定位，不直接执行于主窗口 |
| 组件区域登记不完整 | 双击无响应 | 明确后备到属性栏并提供开发诊断 |
| 发布裁剪遗漏运行依赖 | 成品故障 | 单 HTML/网页包共用转换器并跑兼容示例 |
| 对“源码不包含”的误解 | 安全预期过高 | 文档明确浏览器仍需执行代码，本轮不做 DRM |
