# R0 公式作者编辑技术决策

> 日期：2026-08-11
> 范围：Editor 1.0.0 `FormulaNode`（当时合同写在 Project V8；当前工程是 Course Project V9，公式 AST 合同仍适用）
> 结果：**采用无新依赖的受限线性输入与模板编辑；MathLive 保持在未来隔离试验门禁**

## 1. 目标与不可变边界

目标是让普通作者无需阅读 JSON 或 AST，即可编辑当前 Project V8 已支持的分式、根式、上下标与括号。以下边界不变：

- `FormulaNode.ast` 仍是唯一持久化事实；线性字符串仅为按需派生的作者表示，不进入 Schema。
- 解析失败、V8 Schema 校验失败或存在 `□` 槽位时禁止提交，当前工程保持不变。
- 原始 AST 不再出现于普通或专业公式属性；仅有现有“开发”面板的选中对象 JSON 入口可用于开发者诊断。
- 不增加矩阵、方程组、多行对齐或任意 LaTeX 承诺，不扩大 Project V8 Schema。

## 2. 当前采用方案

### 2.1 可见作者交互

- 双击画布 FormulaNode 直接打开聚焦编辑层；属性栏也使用同一编辑器。
- 可直接输入 `x^2`、`x_i`、`a/b`、`√(x+1)` 等线性形式；`a/b` 解析为竖式 `fraction`。
- 模板覆盖分式、平方根、n 次根、上标、下标、上下标及圆/方/大括号；符号栏提供常用运算符与希腊字母。
- 模板槽位用 `□` 标识，Tab 在槽位间循环；已选公式内容会放入模板的主要槽位。
- 输入过程使用共享公式渲染器实时预览。Enter/“应用公式”提交，Escape/“取消修改”放弃草稿。
- 一次公式提交只产生一条工程历史记录；一次 Undo 还原整次公式编辑。

### 2.2 双向适配

| V8 AST | 常用线性表示 |
| --- | --- |
| `row` | 空格分隔的顺序表达式 |
| `token` | `x`、`2`、`α`；罕见内容使用 `\text{...}` 无损转义 |
| `operator` | `+`、`×`、`≤`；罕见内容使用 `\operator{...}` |
| `fraction` | `a/b` 或 `\frac{a}{b}` |
| `root` | `\sqrt{x}`、`\sqrt[n]{x}` |
| `script` | `x^2`、`x_i`、`x_i^2` |
| `fenced` | `(x)`、`[x]`、`\{x\}`；罕见围栏使用 `\fenced{...}` |

`serializeFormulaAst()` 对罕见 token/operator、单子节点 row 和自定义围栏使用显式转义，已用测试证明 `parse(serialize(ast))` 对当前七类合法 AST 保持结构无损。未知命令不会转为普通文本或占位图片。

### 2.3 无障碍描述

- 新建公式默认使用 AST 派生的可读描述，公式提交时在同一事务中更新。
- 作者手动改写后进入“自定义描述”状态。后续修改 AST 不覆盖该文本，但明确提示复核；可显式恢复自动描述。
- 为避免扩大 Schema，“自动/自定义”不增加持久化开关，而由当前描述与 AST 派生值的等价性判定。

## 3. 为何当前不引入 MathLive

本次权限明确禁止新增 npm 依赖，且尚未完成对 MathLive 的许可证、完全离线资源、包体、Electron 中文输入法、键盘/读屏、撤销协作和当前 AST 子集限制的隔离证明。因此本轮不引入该依赖，也不宣称已具备 Word/MathLive 级的槽位内可视光标、空间键转专业形式或虚拟数学键盘。

若真实教师任务证明当前线性+模板方案仍无法胜任，后续隔离试验必须先通过上述全部门禁，再单独申请依赖决策；不得将 LaTeX/MathJSON 保存为与 AST 并行的第二事实。
