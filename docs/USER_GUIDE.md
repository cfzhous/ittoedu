# 用户指南

本指南适用于 **互动课件编辑器 V1.0.0 内部收敛分支（Windows x64）**，当前工程格式为 Project V8（`schemaVersion: 8`）。Project V8 JSON 是工程的业务真相；当前原生 2D 画布使用 Phaser，DOM/Canvas/WebGL 由运行时或组件按需增强。编辑器是 AI-native 课件的轻量编辑与交付容器：手动模式解决文字、素材、布局、稳定状态、常用映射和事件驱动的入场/退场编排；一次性复杂互动使用场景/全局运行时，高复用且需教师反复配置的能力使用组件。

文档同步基线：**2026-08-07**。1.7.0 原型位于归档标签 `internal-prototype-1.7.0`；当前主干已进入 Project V8 断代，但 Runtime API 1、Component API 1–3 和历史夹具清理尚未完成，不代表内部正式版 1.0 已通过验收。

## 1. 启动编辑器

当前 1.0.0 收敛分支使用源码目录中的双击入口，不构建便携版或安装包：

1. 在 Windows 10/11 x64 安装 Node.js LTS；
2. 拉取或解压完整源码目录；
3. 双击根目录 `启动课件编辑器.cmd`。

入口会先把仓库 `.agents/skills/` 中的两个权威课件 Skill 幂等同步到当前用户的 `%USERPROFILE%\.agents\skills`，首次缺少依赖时再自动执行 `npm ci`，随后构建 Player、Renderer、Electron 并直接打开应用。之后每次双击都会同步 Skill 并按当前源码重新构建，不会调用 `electron-builder`，也不会生成 `release/`、Portable EXE 或安装程序。需要在终端启动时可使用 `npm start`，它同样会自动执行 Skill 安装；也可只运行 `npm run install:courseware-skills`。

Skill 安装器只管理 `orchestrate-courseware` 与 `build-project-v7-courseware`。目标内容未变化时不会重复复制；若用户目录已有非本项目管理的同名不同内容 Skill，安装器会拒绝覆盖并显示警告，编辑器仍可继续启动。安装过程不会删除旧的 `%USERPROFILE%\.codex\skills` 副本。Codex 未立即显示新版本时应重启 Codex。它们属于外部 AI 创作工作流，不代表 Editor 1.x 内置了 AI 生成功能。

仓库中历史 1.6.0 便携版/目录版记录不包含当前 Project V8 能力，不应作为当前版本启动入口或分发物。

根目录入口直接运行项目锁定的 Electron，不提供商业代码签名。请只从可信仓库获取源码，并保留 `package-lock.json`；不要关闭系统安全功能。

源码版编辑器需要本机 Node.js/npm；首次依赖安装需要访问 npm registry。编辑器完成构建后、预览及导出的离线课件不依赖浏览器扩展或本地服务器。

## 2. 认识界面

主窗口分为六个区域：

1. 顶部工具栏：两种模式都保留新建、打开、保存、撤销、重做、模式切换、“整课预览”和统一“导出”；简洁模式把最近工程、另存为和工程检查收进“更多”，专业模式直接显示这些入口，并额外显示“导入组件”。
2. 左侧场景列表：顶部固定“全局层”，其下可查看缩略图，选择、新建、复制、重命名、删除和排序场景。
3. 中央工作区：始终显示同一个 1280 × 720 画布，可在“编辑状态”和“当前位置试运行”之间切换；画面不会换到另一块预览区。编辑状态可选择、框选、移动、缩放和旋转原生节点，当前位置试运行则在原位置接管真实互动。
4. 右侧面板：
   - “元素”是唯一添加与媒体管理入口，不再保留重复的“素材”一级 Tab；“常用”提供文字、图片、视频、声音和全部图形快捷入口，“媒体”只管理已进入工程的图片、视频和声音，专业模式再显示“互动组件 / 控制与全局”及组件包管理；
   - “图层”用于查看叠放顺序、重命名、显示/隐藏、锁定、复制、删除和排序节点；
   - “属性”用于编辑场景、单个节点或多选节点；简洁模式提供常用图文设置和“出现动画”，专业模式追加精确参数、播放初始状态、点击交互与运行时设置；
   - “互动与动画”只在专业模式显示：普通场景编辑 `scene.interactions`，全局层编辑课程级 `globalInteractions`，用于进入事件、音视频生命周期、组件/运行时事件和其他非点击规则；
   - “开发”只在专业模式显示：打开加宽的单任务工作台，在“运行时 / 对象 JSON / 规则 JSON / 组件代码”之间切换，受控修改工程内容。
5. 画布下方状态条：切换当前场景的基础、初始、反馈、完成等命名状态，并设置运行初始状态和场景缩略图状态。
6. 底部状态栏：显示处理状态、当前场景、节点数、选中项和工程是否已命名。

窗口标题中课件名称后的 `*` 表示有未保存修改。

### 2.1 简洁模式与专业模式

两种模式使用同一份 Project V8，只改变工作入口和信息密度。切换模式不产生工程历史、不删除高级规则或运行时，也不会改变预览和导出结果；本机会记住上次使用的模式。

- 简洁模式右侧只有“元素 / 图层 / 属性”，适合添加图文素材、画布排版、常用属性、文字编辑和单元素出现动画；
- 专业模式右侧为“元素 / 图层 / 属性 / 互动与动画 / 开发”，继续开放组件包、完整规则、运行时、对象结构、精确参数和高级声音能力；
- 简洁模式遇到已有专业规则、运行时或组件时只收起高级编辑入口，内容仍按原工程运行。需要调整时切换专业模式。

## 3. 新建、打开、最近工程和保存

### 3.1 新建

单击“新建”或按 `Ctrl+N`。默认工程包含一个名为“场景 1”的白色 16:9 场景，并在全局层放置一个可编辑的画布内教师控制器。控制器跨场景持续存在，默认包含一个点击后展开全部场景的“场景目录”按钮。

如果当前工程有未保存修改，新建或打开其他工程前会确认是否放弃；如需保留请先取消并保存。直接关闭编辑器时会明确提供“保存 / 不保存 / 取消”：选择“保存”会等待当前工程保存成功后关闭；选择“不保存”会清理恢复副本并关闭；选择“取消”继续编辑。

### 3.2 打开工程

1. 单击“打开”或按 `Ctrl+O`。
2. 选择一个 `.h5lesson` 文件。
3. 编辑器校验文件签名、工程版本、数据和包内路径后载入工程。

当前工程 Schema 为 V8。旧 Project V1–V7 不再由主程序载入或逐级迁移；编辑器会在解析前显示“旧工程格式不受支持”，且不会产生可继续保存的半加载工程。V8 工程包含统一全局层、场景状态、场景与全局声明式交互、可顺序/并行的动作步骤、元素入场/退场、声音库、视频节点、结构化教师控制器、`playback.presenter` 合同、场景/全局自由运行时和全局组件。当前 `playback.presenter` 只完成 Schema/保存/发布边界，PageUp/PageDown 输入、附加按键设置与作者命令执行尚未实现，不能据此宣称翻页笔已可用。需要恢复旧工程时，请使用归档标签 `internal-prototype-1.7.0` 对应的旧编辑器或后续独立离线转换工具，并保留原始文件。

如果提示工程损坏或格式版本不支持，请使用兼容版本的编辑器打开，或从备份恢复。不要手工修改工程压缩包中的文件。

#### 3.2.1 体验旗舰课例

在源码环境运行 `npm run build:induction`，然后打开 `output/induction-courseware/不是磁场，而是变化.h5lesson`。建议先在“编辑状态”逐幕查看命名状态和可编辑文案，再用“当前位置试运行”操作预测、磁体运动、共享时间线、方向判断与迁移题，最后用“整课预览”走完整路径，并与同目录离线 HTML 对照交付效果。

### 3.3 最近工程

专业模式顶部“最近工程”和简洁模式“更多”中的“最近工程”都列出最近打开或保存的最多 12 个 `.h5lesson` 文件。单击条目即可打开；文件被移动或删除后，失效条目会在刷新列表时清理。

最近工程只记录本机文件路径，不会上传工程内容。

### 3.4 保存与另存为

- 单击“保存”或按 `Ctrl+S`：新工程会打开保存对话框；已有路径的工程写回当前文件。
- 在专业模式单击顶部“另存为”，或在简洁模式打开“更多”后单击“另存为”；也可按 `Ctrl+Shift+S`。工程会保存到新的 `.h5lesson` 文件，后续“保存”写入新文件。
- 保存成功且保存期间没有发生新修改时，窗口标题中的 `*` 消失；若压缩或写盘期间继续编辑，已写入的是启动保存时的快照，新修改仍保留且 `*` 不会错误消失。

工程文件包含课件数据、素材、自由运行时和已导入组件。移动到另一台电脑时，只需复制 `.h5lesson` 文件。运行时和组件都属于可执行代码，只打开可信来源工程。

### 3.5 自动恢复

发生未保存修改并停止操作约 1.8 秒后，编辑器会异步压缩并在本机应用数据目录写入恢复副本。恢复管线同一时间只运行一份；新修订会取消过期压缩、合并等待中的更新并跳过重复修订，避免连续编辑时并发写盘。正常保存、新建或打开其他工程后，对应恢复副本会被清理。

如果程序异常结束且恢复副本仍在，下次启动会显示恢复提示：

- “恢复课件”：载入副本并将其标为未保存工程；请立即使用“保存”或“另存为”。
- “丢弃副本”：删除该本地恢复数据。

自动恢复不是版本历史或正式备份，也不会自动覆盖原 `.h5lesson`。重要课件仍应定期手动保存并保留外部备份。

## 4. 管理场景

- 选择：单击场景卡片。
- 新建：单击“新建场景”。
- 复制：单击场景卡片右侧的复制按钮；副本插在原场景之后。
- 重命名：双击场景名称，或在未选择节点时使用“属性”面板。
- 背景色：清空节点选择后，在“属性”面板设置场景背景色。
- 排序：拖动场景卡片左侧的把手。
- 删除：单击删除按钮并在确认提示中继续；删除场景可以撤销。

工程至少保留一个场景。建议单个工程控制在 200 个场景以内，防御性硬上限为 1000 个场景。超过建议值仍可编辑，但几小时的大课更适合按章节拆成多个工程。预览与导出按场景列表从上到下播放或生成页面。

### 4.1 管理同一场景的状态

每个场景有一个“基础场景”和至少一个命名状态。基础保存规范元素；命名状态只保存与基础不同的字段，所以基础修改会自动传播给没有单独覆盖该字段的状态。

- 单击“基础场景”：编辑所有状态继承的基础值；
- 单击命名状态：画布立即显示该状态，后续位置、尺寸、显隐、文字、样式、组件参数和背景修改只进入当前状态；
- “新状态”：创建一个继承基础的空状态；“复制”：复制当前状态的全部覆盖；
- 双击状态卡或使用“改名”修改名称；
- “设为初始”：决定进入场景时 Player 首先显示哪个状态；
- “设为缩略图”：决定左侧场景卡片显示哪个状态；
- “清除覆盖”：使当前状态重新完全继承基础；
- 在状态中删除元素只会让它在当前状态隐藏；切回基础删除才会从场景和全部状态中移除；
- 在状态中新建元素只在该状态显示，但仍拥有普通图层、选择框和属性编辑能力。

单个场景最多保存 100 个命名状态。状态卡上的“初始”和“缩略图”徽标是两个独立角色：前者决定进入场景时的画面，后者只决定左侧场景卡的代表画面。

场景缩略图不会执行 JavaScript 运行时，也不执行入场/退场或应用 `playbackInitialVisibility`；它按作者稳定可见性显示节点，并合成已启用的 `scene.runtime.staticFallback` 和 `globalRuntime.staticFallback`。顺序为：背景 → 全局 underlay 元素 → 全局运行时 underlay → 场景运行时 underlay → 场景节点 → 场景运行时 overlay → 全局 overlay 元素 → 全局运行时 overlay。`runtime-layer` 透明叠加；`full-scene` 会在自身层级清除下方合成后铺满画布。未登记静态后备的已启用运行时会显示“运行时”提示角标。

右侧属性面板顶部会标明“基础场景”或当前状态名称。状态中尚未修改的元素显示为继承基础；一旦修改会形成覆盖，可用“恢复基础值”清除该元素在当前状态的全部覆盖。

### 4.2 编辑状态与当前位置试运行

- 两种状态使用同一块 1280 × 720 舞台和同一 Player 视觉源。切换只改变输入与运行权限，不改变画布坐标、组件位置或 DOM/Canvas 合成关系；
- “编辑状态”使用隔离的 authoring Player 显示原生节点、组件、场景运行时和全局运行时的真实合成画面，并在上方叠加透明 Phaser 原生交互层。该透明层只负责选择、框选、移动、缩放和旋转，不重复绘制第二套视觉；
- authoring Player 会冻结学生点击/拖拽、声明式互动、音频和视频播放、导航、状态推进及 `courseState` 写入。运行时与组件仍可创建稳定视觉，因此“看得见”不表示互动正在执行；需要验证真实行为时切换到“当前位置试运行”；
- “当前位置试运行”在原画布位置启用 playback Player，直接从当前场景和当前命名状态开始真实运行组件、场景/全局运行时、事件、媒体和状态切换；如果当前选择的是“基础场景”，则从该场景的初始状态开始。该状态不提供拖拽编辑；
- 编辑状态中的场景/状态选择始终由编辑器决定，authoring Player 不会反向导航或覆盖选择。只有试运行中的场景和命名状态变化会同步高亮左侧场景与下方状态卡；
- 两种状态都把 Player 文档装入不授予同源权限的 sandbox iframe，并使用独立会话标识过滤旧消息；工程与组件素材以可转移二进制缓冲区送入沙箱，再由 iframe 在自身不透明源内创建 Blob URL，避免父窗口 URL 被拒绝和大媒体 Base64 膨胀。切换、重试、关闭或创建失败时会回收临时文档及沙箱素材 URL。载入超时或 Player 启动失败时，中央画布会显示原因和“重试”入口；
- 顶部“整课预览”与此用途不同：它在独立窗口中从第一场景的初始状态开始，适合验收完整流程。

## 5. 添加元素与复用素材

“元素”面板顶部可搜索元素、图形、素材或组件。简洁模式只提供“常用 / 媒体”两个分类：“常用”包含文本、图片、视频、声音和全部图形快捷入口；“媒体”只管理已进入工程的声音、视频和图片，不重复显示快捷入口或导入按钮；专业模式再增加“互动组件 / 控制与全局”。搜索会跨分类筛选可添加内容，清空搜索后返回当前分类。文字、图片、视频、基础图形和已导入组件支持两种添加方式；声音通过“常用”中的快捷入口导入：

- 单击条目：添加到画布默认位置。
- 将条目拖入画布：添加到松开鼠标的位置。

建议每个场景控制在 250 个节点以内，防御性硬上限为 1000 个节点。超过建议值时状态栏会提示使用网页包；一次性复杂视觉可由场景运行时承载，高复用能力可组合为职责清晰的互动组件，不要在单场景无节制堆叠节点，也不要为一次性效果强行组件化。

### 5.1 简洁模式的出现动画

简洁模式下，选中场景元素后直接在“属性”→“出现动画”选择：

- 效果：无、淡入、滑入或缩放；
- 滑入方向：从左、右、上或下；
- 速度：快速、标准或舒缓；
- 延迟：不延迟、0.3 秒、0.6 秒或 1 秒。

选择效果后，编辑器会在一次可撤销操作中同时创建当前场景/状态的 `node.activated → node.enter` 规则，并把该元素的 `playbackInitialVisibility` 设置为 `hidden`；选择“无”会成对移除这条简洁规则和对应初始隐藏。编辑画布仍保持元素可见，预览、撤销和重做都不需要再手工协调两处设置。若元素已有可能重叠的专业入场规则，简洁模式不会覆盖，而是提示切换到专业模式。

### 5.2 专业模式的事件动画与规则

专业模式在“属性”→“通用”开放“互动播放初始状态”：

- “遵循作者可见性”（`inherit`）：Player 初始按节点或当前命名状态的 `visible` 显示；
- “初始隐藏，等待入场”（`hidden`）：只在互动 Player 中先隐藏，等待规则执行 `node.enter`。

“互动与动画”把每条完整规则按“当 / 如果 / 就”组织，并提供自然语言摘要、搜索/筛选、常用模板和可读动作顺序。需要超出简洁出现动画的编排时：

1. 选择业务触发点，例如按钮点击、进入场景/状态、组件或运行时事件、音视频事件、节点激活，或指定动画步骤完成；
2. 添加“元素入场”（`node.enter`）或“元素退场”（`node.exit`），选择目标节点、立即/淡化/滑动/缩放、滑动方向、时长与缓动；
3. 为每个动作步骤设置局部延迟，并选择“上一组完成后”（`after-previous`）或“与上一步同时”（`with-previous`）；连续的 `with-previous` 形成一个并行组；
4. 需要跨规则接力时，再以该步骤稳定 ID 选择“动画完成”（`animation.completed`）触发器。

入场会先建立 Player 瞬态可见性；退场会立即禁用该元素输入，完成后瞬态隐藏。它们都不会改写节点 `visible`、不切换 `scene.presentation`、不把动画进度存入工程。同一规则尚未完成就再次触发时，旧运行会取消并从动作规范起点重播；不同规则争用同一节点时，新动画从当前帧接管。被取消的动画不发 `animation.completed`。编辑画布、场景缩略图、PDF/PPTX 和其他静态捕获不应用 `playbackInitialVisibility`，始终按作者稳定可见性展示，以便选择和修改。

同一条规则在上一次尚未完成时再次触发，Player 会取消旧运行并从新触发点重启，避免同一规则的延迟和动画无限叠加。

本编排能力不是通用关键帧或路径时间轴。连续路径、物理、粒子或算法动画继续由组件或自由运行时完成。

## 6. 文本与富文本

### 6.1 编辑文字

1. 在“元素”中添加“文本”。
2. 单击文字选择整个文本节点。
3. 双击文字进入就地编辑；也可在“属性”中单击“编辑局部文字格式”。进入时文字默认全选，可重新拖选需要设置样式的片段。
4. 输入完成后按 `Ctrl+Enter` 提交，按 `Escape` 取消，或单击编辑区外提交。

中文输入法候选阶段不会被误判为提交。

### 6.2 局部富文本

就地编辑上方的浮动工具栏可对当前文字选区设置：

- 加粗、斜体、下划线、删除线；
- 黄色高亮、取消局部高亮；
- 局部文字颜色。
- 清除所选内容的局部格式，使其重新继承整段样式。

局部样式会跟随文字一起保存、预览和导出。在“属性”面板直接改写整段“文字内容”时，编辑器会按未改变的前后文字重新映射原有局部样式；被删除文字对应的样式会随之删除。

### 6.3 整体文字样式

选择单个文本节点后，可在“属性”面板设置：

- 字体、字号、文字颜色、加粗、斜体、下划线、删除线和整段高亮；字体列表同时显示中文名称、实际 CSS 字体名和当前设备的“可用/未安装”状态，输入中文名或 CSS 名均可过滤，也可按 Enter 使用自定义字体或回退字体串；
- 行距、字距、内边距；
- 水平左/中/右对齐及垂直顶/中/底对齐；
- 横排、列从右向左的竖排，或列从左向右的竖排；旧工程中的 `vertical` 会按右起竖排兼容打开；
- 文本框背景色、背景透明度和圆角；
- “自动尺寸”“固定尺寸并裁切”“自动缩小字体”三种溢出策略。自动尺寸在横排时自动增高并允许调宽，在竖排时保持可调高度并自动增宽，因此竖排文本框可以直接输入高度或拖动画布上下边缘纵向拉长。

单 HTML、网页包和 PPTX 都不会自动嵌入用户自行填写的系统字体文件。跨电脑分发时，优先使用目标电脑常见字体，并在最终目标设备上检查换行和字形；PDF 会固定当前电脑上的渲染结果，PPTX 中普通横排和右起竖排文字仍可编辑，因此缺少字体时可能发生替换和重新换行。PowerPoint 的原生东亚竖排不支持列从左向右，为避免静默颠倒列顺序，左起竖排在 PPTX 中会按稳定画面转为图片。

所有名称为“透明度”的编辑器控件都使用同一含义：`0%` 表示完全不透明，`100%` 表示完全透明。工程内部仍保存不透明度数值，旧工程无需迁移。

## 7. 图片与媒体

### 7.1 导入和替换

1. 单击“图片”或把“图片”拖入画布。
2. 从系统对话框选择 PNG、JPEG、WebP、GIF 或 SVG。
3. 如需更换素材，选中图片后在“属性”中单击“替换图片”。
4. 已导入图片会同时出现在“元素”→“媒体”→“图片素材”；需要再次使用时单击“添加到画布”，会创建引用同一工程素材的独立可编辑图片元素，无需重复导入文件。

图片扩展名必须与实际内容一致，单张图片不得超过 100 MB。读取失败时，可先使用图片软件重新导出后再试。

### 7.2 显示方式

- “适应（完整显示）”：完整显示图片，节点框内可能留空。
- “填充（允许裁剪）”：铺满节点框，超出部分被裁剪；用“填充焦点 X/Y”决定保留区域。
- “拉伸”：图片直接匹配节点框，可能改变原始比例。

“左/右/上/下裁剪”会从源图片对应边缘真正移除内容，四项都为 0 时显示完整源图，可随时用“重置裁剪”恢复。适应模式还可调整图片在框内的位置；拉伸模式不显示无效的焦点控件。

还可设置保持宽高比、水平/垂直翻转、圆角，以及矩形边缘或椭圆/径向羽化。关闭“保持宽高比”后可自由改变宽高；开启后角点和四条边的缩放手柄都会保持比例。

### 7.3 声音库与声音映射

在“元素”→“常用”中选择“声音”，可导入 MP3、OGG、WAV 或 M4A。每个声音库条目都有稳定 `soundId`；导入后到“媒体”中试听、重命名和删除，切换专业模式后还可设置：

- 声道：背景音乐、旁白、音效或界面提示音；视频音量由独立的 `video` 声道统一管理；
- 默认音量和是否循环；
- 播放生命周期：声明式动作可指定随当前场景结束，或在课程范围持续；
- 已在交互规则中引用的声音不能直接删除，应先删除或改写对应映射。

专业模式下，“元素”→“媒体”中的“全局声音设置”可修改成品默认静音、主音量、背景音乐/旁白/音效/界面提示音/视频五个声道音量，以及旁白压低背景音乐的开关和目标音量；这些修改支持撤销和重做。Player 会按工程设置应用 ducking 淡变；浏览器阻止自动播放时，背景音乐和旁白会等待首次用户手势重试，短促音效不会无限排队。交互规则通过 `soundId` 或声道执行播放、暂停、继续、停止和切换静音，并可为播放/继续设置淡入、为暂停/停止设置淡出，不依赖素材文件名或物理路径。

### 7.4 视频素材与 VideoNode

在“元素”→“常用”中选择“视频”，支持 MP4 与 WebM；导入后可在“媒体”的“视频素材”中管理。素材条目显示文件名、时长、文件大小和尺寸；每次单击“添加到画布”都会创建引用同一素材的独立 `VideoNode`，之后可像其他节点一样选择、删除、拖拽、缩放、旋转、排序和按场景状态覆盖。

视频属性包括适应/填充/拉伸、自动播放、循环、静音、音量、播放速度、开始/结束时间、封面图片或视频帧、表面点击切换播放以及简易画布控制。播放器会把视频音量纳入全局静音和 `video` 声道；还可设置视频开始时对背景音乐不处理、临时压低、临时暂停或永久停止，暂停/结束/销毁视频时会恢复临时处理，永久停止不会恢复。视频开始、暂停、结束及播放到指定秒数也可作为声明式交互触发器。编辑状态只显示封面或指定视频帧，不自动播放；真实播放请在“当前位置试运行”或“整课预览”中验收。

视频表面点击保留给视频本身的播放控制，因此视频节点不再提供“连接到状态”快捷按钮。需要根据视频推进状态或场景时，切换专业模式，在“互动与动画”使用视频开始、暂停、结束或到达时间点；需要显式由教师点击跳转时，在视频上方放置独立按钮或透明图形热点。旧工程中的视频 `node.click` 规则不会被删除，但只有同时关闭“点击切换播放”和原生 controls 后才能接收表面点击。启用内置点击/controls 与旧点击规则冲突时，编辑器会显示诊断；循环视频配置 `video.ended` 规则时也会提示结束事件通常不可达。

## 8. 图形库

Editor 1.0.0 内置以下图形：

- 基本：矩形、圆角矩形、圆/椭圆、三角形、菱形。
- 线条与箭头：直线、折线箭头、左/右/上/下箭头、双向箭头。
- 括号与着重：左/右/上/下大括号、横向/纵向大括号对、左/右方括号、着重圆点、着重三角。

选中图形后，可更换图形类型并设置填充色、填充透明度、边框/线条颜色、透明度和宽度，以及实线、虚线或点线。透明度同样是 `0%` 完全不透明、`100%` 完全透明。矩形支持圆角；直线与折线箭头还可分别设置起点和终点箭头，箭头样式包括三角、尖角、圆点和菱形。

## 9. 互动组件

互动组件属于专业能力。先切换到专业模式，再执行：

1. 单击顶部“导入组件”。
2. 阅读安全提示，仅在来源可信时继续。
3. 选择 `.h5component` 文件。
4. 导入成功后，组件出现在“元素”→“互动组件”。
5. 单击组件条目，或把它拖入当前场景。

编辑模式始终可以把组件作为整体选择、移动、缩放和旋转。V1 组件只支持这种原子级编辑；V2 组件可显式公开文字、长文本、数字、开关、颜色、选项和工程图片，并提供页面、变体和预设；V3 组件还会自动把 `props.content` 中所有文字显示在“属性”面板，并可声明场景或全局作用域；V4 在此基础上声明 DOM、Phaser 或 hybrid 渲染能力，并支持显隐、暂停/恢复和静态捕获准备。V1–V3 旧包仍可导入。

组件由统一画布中的 authoring Player 直接显示。左侧场景缩略图优先绘制组件包 `manifest.thumbnail` 指定的图片；组件未提供缩略图或图片解码失败时，编辑器会绘制带组件名称的边框后备框，因此组件不会再从缩略图中无声消失。编辑状态冻结组件互动，只保留稳定视觉与显式编辑目标；真实互动仍需在“当前位置试运行”或“整课预览”窗口验收。

V2/V3/V4 预设会在“已导入组件”下显示为独立条目，可点击或拖入画布。组件内部按钮、拖拽、动画和场景跳转只在预览、单 HTML 与网页包中运行。组件可以控制指定场景跳转、上一页、下一页、重播本页和重开课件。

### 9.1 组件画布文字编辑

组件作者可以显式开放稳定文字区域。编辑状态下双击已登记区域，会在该区域上显示轻量输入框，直接修改组件实例 Props；单行文字按 Enter 提交，多行文字按 `Ctrl+Enter` 提交，按 `Esc` 取消。修改支持撤销/重做，处于命名状态时写入当前状态覆盖。试运行、整课预览和成品播放器不会出现编辑命中区。

宿主不会猜测组件画面中的文字。DOM 组件只有带 `data-courseware-edit-key="content.title"` 的元素可命中；Phaser/hybrid 组件只有通过可选、仅编辑态的 `ctx.editor.registerTextRegion({ key, getBounds })` 登记的区域可命中。兼容上下文类型 V1–V4 都可能在隔离 authoring Player 中看到这一可选字段并必须判空；当前位置试运行、整课预览、普通 preview、capture 和成品 Player 均不提供 `ctx.editor`。`key` 还必须对应 manifest 已公开的 `text` / `textarea` 字段或有效 `props.content` 字符串；V1 通常没有此类公开字段，因此仍作为整体组件编辑。

未登记区域仍把组件作为整体选择；旧组件继续在“属性”中修改公开文字，不会报错或改变播放行为。协议细节见 [组件开发指南](COMPONENT_AUTHORING.md)。

### 9.2 组件包管理与故障隔离

专业模式“元素”面板底部的“组件包管理”把组件包作为工程一等资源管理：

- 每个包显示名称、稳定包 ID、版本、场景实例数和全局实例数；
- “选择新包替换”只接受同 ID 的新包，并校验新包是否仍支持所有现有实例所在的场景/全局作用域；成功后全部实例同步到新版本；任一校验或导入步骤失败时保留原包和原实例；
- 只有场景和全局实例数都为 0 时才能删除包；仍被引用时按钮禁用并说明需要先删除哪些实例；
- 单个组件创建、属性/尺寸/显隐/暂停更新、捕获准备或销毁失败由宿主隔离并记录诊断，不应让整页其余内容停止工作。遇到问题可在“工程检查”定位包引用，并导出诊断报告交给组件作者。

### 9.3 统一全局层

单击场景列表顶部“全局层”即可进入类似 PPT 母版的统一编辑层。这里可以直接添加文字、图片、视频、基础图形、画布内教师控制器，以及 manifest 明确支持 `global` 的 V3/V4 组件；通用标题、Logo、页眉页脚、导航和装饰无需复制到每个场景，也无需包装成组件。

全局层中的每个元素都可编辑位置、尺寸、旋转、叠放顺序、`underlay/overlay` 和场景可见范围：

- `all`：所有场景可见；
- `include`：只在指定稳定场景 ID 中可见；
- `exclude`：除指定场景外可见。

V4 DOM/hybrid 组件有一个明确例外：它的 DOM 部分位于固定组件 DOM 平面，整体在 Phaser Canvas 上方，因此不能靠选择 `underlay` 压到原生 Canvas 节点背后；`underlay/overlay` 仍控制它的 Phaser 代理/Phaser 部分。确需 Canvas 后景的组件应使用 Phaser 渲染，或由运行时 DOM underlay 承载后景。

播放器只创建一份全局元素，普通翻页和重播本页时不会重建。隐藏元素会关闭显示和输入；全局组件的内部状态也会保留，只有“重开课程”才销毁并重建整个全局作用域。

### 9.4 场景与全局运行时文字

V7 工程可由 AI、生成脚本或专业模式“开发”面板写入 `scene.runtime` 和 `globalRuntime`。新运行时使用 API 2，并严格声明 `dom`、`phaser` 或 `hybrid`；API 1 旧内容继续兼容。属性栏会显示运行时登记的全部 `content.values` 文案，普通教师可直接修改、保存并同步到预览和网页导出；修改 `renderMode` 不会自动转换 DOM/Phaser 实现。

场景或全局运行时如果显式启用 Runtime Authoring V1，还可把文字或图片区域开放到对应画布作用域：文字目标必须对应 `content.values` 中已有的键，图片目标必须对应 `assets` 中已有的绑定。编辑状态下双击目标即可原位修改文字或选择替换图片；运行时不能借此访问工程 Store。`scene.runtime` 的内容由当前场景的基础及全部命名状态共享，`globalRuntime` 的内容由整课共享，均不会生成某个状态专属覆盖。

没有声明 authoring 版本或目标的旧运行时仍由 Player 完整显示，不会变成空框，也不会自动扫描像素推断可编辑内容；其文字、素材绑定和源码继续从“属性”或专业“开发”面板修改。Runtime Authoring V1 与 Runtime API 1/2 是两条独立版本线，不需要为开放目标把新 API 2 运行时降级。

题目、答错、答对、完成等稳定画面应使用场景状态和可编辑元素；场景运行时负责判定、事件、过渡和瞬态效果，并切换这些状态。跨场景一次性规则可以由全局运行时实现，不必包装成组件。不得把整页稳定 UI 只放进自由运行时；人工可见文字仍必须登记并可编辑。

地球、太阳系、立体几何等真 3D 可以由具体运行时或 V4 组件携带 Three.js 实现，不要求编辑器核心内置 Three.js。程序化的一次性 3D 可直接使用运行时；带模型、较大或可复用的 3D 默认把离线 GLB 放进 V4 组件包。当前“媒体”管理还没有独立“模型”类型，不能把 GLB 当图片导入；没有 3D 的课件不会承担该能力。教师仍通过运行时 `content.values` 或组件 `props.content`/公开参数修改允许编辑的内容。

组件包含浏览器 JavaScript。它没有 Node.js 和 Electron 权限，但 Editor 1.0.0 不是完整代码沙箱；可信组件仍可修改或阻塞课件页面自身。不要导入来源不明的组件。

组件包不得超过 50 MB，根目录必须包含 `manifest.json` 和 manifest 指定的普通 JavaScript 入口。制作组件请参阅 [组件开发指南](COMPONENT_AUTHORING.md)。

### 9.5 专业“开发”面板

“开发”是专业模式中的受控工程工作台，不是编辑器自身源码入口。进入后右侧栏会加宽，顶部以“运行时 / 对象 JSON / 规则 JSON / 组件代码”显示各任务的当前状态；一次只打开一类内容，避免多个代码框纵向堆叠。代码区使用较大的等宽字号并关闭自动折行。当前提供：

- 当前场景或全局运行时源码：没有运行时时可创建最小 Runtime API 2 模板；应用前检查源码体积、禁止的模块语法、JavaScript 语法和运行时文档结构；
- 所选对象 JSON：允许修改通过 Project Schema 校验的字段，但对象 ID 和类型不可更改；
- 当前规则 JSON：继续使用标准 `trigger / conditions / actions` 结构，规则 ID 不可更改；
- 所选组件的 manifest/runtime：导入的第三方组件默认只读；只有在场景“基础”或全局层单击“创建可编辑副本”，编辑器才会生成带明确来源标记的新包 ID/版本、保留原包，并把当前实例切换到工程内副本。命名状态只能覆盖组件 Props，不能替换组件包，需先返回“基础”。副本通过包路径、入口、缩略图、素材、运行时 API、注册身份和现有实例作用域校验后，才允许修改 manifest/runtime。

应用成功的运行时、对象、规则和可编辑组件修改都会进入工程撤销历史。代码不在编辑器主窗口执行；使用“试运行”仍会进入现有隔离播放器。此处不提供文件系统浏览、Shell、依赖安装、Node/Electron API 或编辑器源码修改，也不承诺组件/运行时源码保密：工程作者态本来就包含这些代码，互动成品中的执行逻辑也可被有技术能力的人恢复和分析。

第三方组件的“只读”只防止在当前工程中直接覆盖原包，不阻止查看或复制已经交付给用户的代码，也不替代组件许可证。创建可编辑副本前应确认授权允许修改和二次分发。

### 9.6 声明式交互规则与教师控制器

专业模式把声明式交互按来源与作用域分为两个编辑区，而不是把关系写死在运行时代码里：

- 普通场景中的规则保存在 `scene.interactions`；进入“全局层”后，点击规则和非点击规则改为保存在课程级 `globalInteractions`，不会复制到每个场景；
- 选中普通节点或全局元素时，“属性”面板显示“交互”，只编辑该元素的单击规则，并可用“连接到状态”快速建立映射；全局规则还可选择“生效场景”，底层以 `scene.in` 条件保存。视频节点不提供该快捷入口，因为其表面点击默认属于播放控制；
- 右侧“互动与动画”不依赖清空节点选择，只编辑非点击规则，可新增进入场景、进入命名状态、节点激活（`node.activated`）、动画完成（`animation.completed`）、声音结束、视频生命周期/时间点、组件事件和运行时事件触发；全局规则也可按场景限制。运行时事件必须明确选择“当前场景运行时”或“全局运行时”；
- 两个编辑区共用同一套状态条件、动作步骤时序和动作编辑器。同一条 `node.click` 规则不会在“互动与动画”中重复出现。面板以“当 / 如果 / 就”解释机制，并提供自然语言摘要、搜索与筛选、常用模板和顺序/同时动作标记。

常用配置流程是：

1. 选择触发器，例如某节点点击、进入场景/命名状态、节点激活、指定动画步骤完成、组件事件、带场景/全局来源的运行时事件、声音结束或视频事件；
2. 按需添加“当前场景属于……”（`scene.in`，主要用于全局规则）和“当前呈现状态属于……”（`presentation.in`）条件；同一条件内多个 ID 按“或者”，不同条件按“并且”判断；
3. 添加动作步骤：元素入场/退场、切换命名状态、跳转场景、上一页/下一页/重播/重开，以及声音或视频控制。每一步都有稳定 ID、局部延迟和 `after-previous` / `with-previous` 启动方式；
4. 连续 `with-previous` 步骤并行启动；下一个 `after-previous` 等待整个并行组完成。只有正常完成的入场/退场才发出可供其他规则使用的 `animation.completed`；
5. 把场景导航、重播或重开放在最后一个独立动作组。选择“跳转场景”时可配置高级 `scene.go.targetStateId`，留空则进入目标初始状态；
6. 需要复用或调整规则优先级时，使用规则卡片的“复制 / 上移 / 下移”。复制会生成新的规则与动作 ID，排序只在同类规则中进行，两者都进入撤销历史。

最常见的状态关系不需要写运行时：同场景可直接配置“点击按钮节点 → 切换到某状态”，跨场景可配置“点击按钮节点 → 跳转场景并进入指定状态”。目标状态会在目标节点、组件和运行时创建前一次性物化，不会先显示初始状态再跳变；目标状态失效时安全回退到目标场景初始状态。复杂判定、拖拽轨迹、程序动画和大量动态数据仍由场景运行时或组件处理，优先发出语义化 `runtime.event` / `component.event`，再由专业模式“互动与动画”映射到稳定状态、声音、视频或导航结果。

直接重复一个或多个节点时，编辑器会为每个副本各复制一次对应的单击规则，并把触发节点改为新 ID；非点击规则不会随节点重复。复制完成后仍应在“当前位置试运行”检查目标场景/目标状态、声音和视频引用是否符合教学意图。

新工程默认的教师控制器是 `globalLayer` 中的 `TeacherControllerNode`。它本身属于画布内容，位置、尺寸、标题、进度、配色、透明度和圆角均可编辑；成品不会额外出现第二套导航栏。

控制器可配置 1–12 个按钮。默认“场景目录”动作为 `scene.open-picker`：点击后展开所有场景，高亮当前场景，选择任一项后跳转并进入该场景的初始状态；目录不提供状态选择。展开、滚动、焦点与当前项高亮只是 Player 临时 UI，点击外部、Esc、选择场景、折叠控制器、发生导航或销毁时关闭，不写入工程、命名状态或 `courseState`。

上一场景、下一场景、重播当前场景、重新开始课程、切换静音和切换全屏仍是标准动作。只在业务明确要求某个固定目标按钮时，才使用高级 `scene.go`，并可选配置 `targetStateId`；它不是默认场景目录的实现方式。

开启“允许折叠”后，控制器出现“收/展”按钮；“打开课件时默认折叠”决定首次创建时的状态。运行中手动折叠或展开不会改写工程，但同一全局控制器实例在普通跨场景切换和“重播当前场景”时保留当前折叠状态；“重新开始课程”会重建全局作用域并恢复工程配置的默认状态。编辑画布可临时点击“收/展”预览，临时状态同样不写入工程。

## 10. 选择、移动、缩放和旋转

### 10.1 单选和多选

- 单击节点：只选择该节点。
- `Ctrl` / `Shift` + 单击：在当前选择中添加或移除节点。
- 在画布空白处拖动：框选与选框相交的可见节点。
- `Ctrl` / `Shift` + 框选：把框选结果加入当前选择。
- `Ctrl+A`：选择当前场景全部节点。
- 单击空白处或按 `Escape`：清除选择。

在“图层”面板中也可使用 `Ctrl` / `Shift` + 单击进行多选。

### 10.2 变换

- 拖动节点：移动单个节点；拖动多选中的任意未锁定节点可整体移动所选未锁定节点。
- 拖动八个控制点：缩放；多选时按整个选择框比例调整各节点的位置和尺寸。
- 拖动选择框上方的圆形手柄：旋转；多选时围绕选择中心旋转。
- 缩放时按住 `Shift`：保持当前宽高比。开启“保持宽高比”的图片会在全部缩放手柄上自动保持比例。
- 旋转时按住 `Shift`：以 15° 为步长吸附。

拖动时会吸附画布边缘、中心和其他节点的边缘/中心，并显示参考线。按住 `Alt` 可临时关闭移动吸附。节点至少保留一部分在画布内，最小尺寸也会受到限制。

“属性”面板可输入精确的 X、Y、宽、高、旋转角度和透明度；透明度 `0%` 表示完全不透明，`100%` 表示完全透明。方向键每次微移 1 像素，`Shift` + 方向键每次微移 10 像素。

### 10.3 画布视图缩放与平移

编辑状态右上角提供缩小、当前比例、放大和“适合窗口/复位”控件。缩放范围为 50%–200%，步进 5%；也可按住 `Ctrl`（兼容 `Command`）滚动鼠标滚轮。按住空格再用鼠标左键拖动，或直接按住鼠标中键拖动，可以平移画布视图；这只改变观察位置，不会修改节点坐标。单击“适合窗口”会把缩放与平移复位到 100% 和画布中心。

缩放和平移只在“编辑状态”生效。“当前位置试运行”在同一工作区恢复完整 Player 输入与默认视图，避免把编辑视图状态误当成课件内容。

### 10.4 对齐、分布和批量操作

选择至少两个未锁定节点后，“属性”面板提供左对齐、水平居中、右对齐、顶对齐、垂直居中和底对齐。选择至少三个未锁定节点后，还可执行水平等距或垂直等距分布。

锁定节点仍可被选中，但不会参与移动、缩放、旋转、微移、对齐或分布。多选属性还支持全部显示、全部隐藏、全部锁定、全部解锁、复制所选和删除所选。

## 11. 图层管理

“图层”面板显示当前编辑作用域的一层节点列表；普通场景显示场景节点，全局层显示全局文字、图片、视频、图形、教师控制器和组件。Editor 1.0.0 不支持分组或嵌套。列表最上方就是该作用域画面最上层。

每个图层可执行：

- 单击选择，`Ctrl` / `Shift` + 单击多选；
- 双击名称重命名；
- 显示或隐藏；
- 锁定或解锁；
- 复制或删除；
- 拖动左侧把手改变前后层级。

隐藏图层不会出现在预览和导出中。锁定只保护编辑操作，不影响预览和导出显示。

运行时/组件内部的 DOM 与 Phaser 对象不等于这里的普通节点图层。Player 使用固定的粗粒度平面：运行时 DOM underlay → Phaser Canvas → V4 组件 DOM → 运行时 DOM overlay；不同渲染器之间不能按每个对象任意穿插。DOM/hybrid 组件整体跟随组件框，但其 DOM 部分位于 Canvas 上方。需要精确交错的定制内容应由作者在同一渲染器中完成，或拆成明确的前景/后景。编辑器不会把 DOM、Phaser 或 Three.js 内容自动互转。

## 12. 复制、撤销和重做

- `Ctrl+C`：把所选节点复制到编辑器内部剪贴板。
- `Ctrl+V`：粘贴并轻微偏移副本。
- `Ctrl+D`：直接重复所选节点。
- `Delete` / `Backspace`：删除所选节点；文字就地编辑时只删除文字。
- `Ctrl+Z`：撤销。
- `Ctrl+Y` 或 `Ctrl+Shift+Z`：重做。

历史记录最多保留 50 步。新操作会清除已经撤销的后续分支；打开其他工程或新建工程时会清空历史。复制/粘贴使用编辑器内部剪贴板，不会读写 Windows 系统剪贴板中的其他内容。

## 13. 整课预览

单击顶部“整课预览”后，编辑器使用与单 HTML、网页包相同的 Player Runtime，在独立安全窗口中从第一场景的初始状态打开当前课件。它用于验收完整课程路径；若只想从正在编辑的场景/状态就地验证，请使用中央“当前位置试运行”。

- 画布内教师控制器的默认“场景目录”展开全部场景，选择后只进入目标初始状态；固定场景/状态跳转是高级按钮动作。普通翻页与场景重播保留折叠状态，课程重开恢复默认折叠状态。
- 开启键盘导航时，左/右方向键仍可切换上一/下一场景。
- 调整窗口大小：课件保持 16:9 等比适配。
- 声明式交互、视频和互动组件：按工程配置响应点击、音视频事件、状态切换、拖拽或其他交互。
- 元素入场/退场在对应规则触发器发生后执行；顺序、并行、延迟和完成事件均按 Project V8 步骤语义运行。复杂运行时/组件动画按各自逻辑运行。

“重播本页”只重建当前场景的原生节点、场景组件和场景运行时；统一全局层、全局运行时和课程进度状态保留。“重开课程”会清空课程状态，重建全局/场景作用域并回到第一场景。两者语义不同。

关闭整课预览窗口不会修改工程。预览内容由主进程内存中的受控协议提供，窗口关闭时释放，不会把当前课件写成临时 HTML 文件。

## 14. 导出单 HTML、网页包、PPTX 和 PDF

单击顶部“导出”后选择格式。四种格式的关键区别：

导出前建议先运行“工程检查”：专业模式可直接单击顶部入口，简洁模式从“更多”打开。面板集中检查丢失/错误类型素材、无效场景或状态跳转、全局与场景交互引用、控制器按钮、组件包、运行时绑定与静态兜底，并按“错误 / 提醒 / 建议”显示数量。每项都可“定位”到相关场景、状态、元素或面板；检查本身不会修改工程。存在“错误”时所有成品导出都会被阻断并自动打开问题列表，必须先修复；提醒和建议不阻断。

“导出诊断报告”与工程检查用途不同：它导出主进程、编辑器、预览和组件的本地异常日志及版本/平台信息，不包含课件素材内容，适合在崩溃、预览或组件异常时交给开发者排查。它不是课件内容清单，也不会自动修复问题。

| 格式 | 生成方式 | 保留互动 | 后续编辑 | 推荐用途 |
| --- | --- | --- | --- | --- |
| 单 HTML | 单向编译的发布数据、素材和 Player 全部内联 | 是，含声音和视频 | 不能恢复工程；回到原 `.h5lesson` 编辑 | 小中型课件、最方便的单文件传递 |
| 网页包 | ZIP 内分离 `index.html`、唯一发布数据、Player 和运行素材 | 是，含声音和视频 | 不能恢复工程；回到原 `.h5lesson` 编辑 | 大型课件、视频或资源较多、静态网站部署 |
| PDF | 捕获 Canvas、DOM、全局层和场景层的 16:9 合成画面 | 否 | 不可拆分编辑 | 打印、审阅、归档 |
| PPTX | 原生节点逐对象导出，组件和运行时静态化 | 否 | 原生文字/图形/图片可编辑；静态化内容整体调整 | 素材提取、二次排版、汇报整合 |

### 14.1 导出单 HTML

1. 单击顶部“导出”→“单 HTML”。
2. 选择文件名和保存位置。
3. 在系统浏览器中双击 `.html`，逐页检查布局和组件交互。

HTML 不需要同目录资源、服务器或网络，移动课件时只需复制这一个文件。文件内 CSP 会阻止网络连接，因此组件不应依赖在线 API、CDN 或远程素材。单 HTML 使用 PublishedLesson V1，不包含可直接导入的 Project V8、历史记录、编辑器字段、组件 manifest 或独立原始 `runtime.js`；互动执行代码仍会以可恢复的编码形式随成品交付，因此不能把它视为加密或 DRM。

预计文件超过 50 MB 时，编辑器会显示体积、解释启动和内存风险，并推荐改用网页包；可以在未超过 256 MB 时选择继续。超过 256 MB 后必须改用网页包。视频在单 HTML 中会转成 Base64，体积还会额外膨胀并提高启动峰值内存，因此只要包含较大的视频，即使尚未触发硬限制，也建议优先网页包。

### 14.2 导出网页包

1. 单击顶部“导出”→“网页包”。
2. 保存 `.zip` 文件并完整解压。
3. 打开解压目录根部的 `index.html` 检查翻页和互动。

网页包把播放器、唯一的 `course-data.js` 发布数据、图片、声音、视频和组件运行素材分开存放，避免把全部 Base64 内容塞进一个 HTML。它不包含 `project.json`、组件 `manifest.json`、独立组件 `runtime.js` 或源码映射。复制或上传时必须保留整个目录结构，不能只复制 `index.html`。它支持直接通过 `file://` 离线打开；正式部署时建议把整个目录放到静态 Web 服务器。技术细节见 [PublishedLesson V1 发布格式](PUBLISHED_LESSON_V1.md)。

### 14.3 导出 PDF

1. 单击顶部“导出”→“PDF”。
2. 等待全部场景渲染。
3. 选择保存位置并打开 `.pdf` 检查。

PDF 每个场景一页，页面为 Player 的静态合成画面，按固定 DOM underlay、Phaser Canvas、组件 DOM/WebGL、DOM overlay、场景层和全局层捕获。运行时/组件会先逐实例执行捕获准备、等待已登记的有限加载任务，并立即冻结各自 Canvas/WebGL 最终帧。Player 已成功启动后，某一场景捕获失败只让该页改用带诊断信息的静态后备，其余页面继续使用真实捕获；只有捕获宿主无法初始化时才对全部页面统一后备。声明式交互、声音和元素入场/退场不会保留；`playbackInitialVisibility: 'hidden'` 不应用，节点按作者稳定可见性捕获。视频保持封面或首帧，不会播放。画布内教师控制器默认不进入静态导出，除非节点明确启用静态导出。

### 14.4 导出 PPTX

1. 单击顶部“导出”→“PowerPoint（PPTX）”。
2. 等待全部场景对象生成。
3. 选择保存位置并用 PowerPoint 或兼容软件检查。

PPTX 使用 16:9 宽屏版式，每个场景一张幻灯片，并按编辑器中的前后层级逐个生成对象：

- 文字导出为 PowerPoint 原生文本框，可直接改字并调整常用文字样式；
- 基础图形优先导出为 PowerPoint 原生形状，可调整填充、线条、大小和旋转；
- 图片导出为独立图片对象，裁剪、圆角、翻转和羽化效果会合成进该图片；
- 视频导出为带文件名的静态视频封面/占位，不保留播放、声音和时间事件；
- 画布内教师控制器默认省略；显式启用 `includeInStaticExports` 时只保留静态外观，按钮不工作；
- 互动组件按实例依次创建隔离捕获 Player，导出为独立的透明静态图片，可移动、删除、复制和重新排版，但暂不保留点击、拖拽、动画等行为；单个实例失败只为该实例生成诊断占位，已经成功的组件快照继续保留；
- 当前场景可见的全局原生文字、图片和图形继续按独立可编辑对象导出，全局组件按独立静态图片导出；
- 场景/全局运行时会优先由隐藏 Player 捕获实际 underlay/overlay 透明快照；失败按场景/全局运行时条目和图层单独记录，只回退对应条目，不清空其他成功快照。捕获失败或未产生可见结果时才使用工程登记的静态后备画面。`runtime-layer` 只叠加运行时层，`full-scene` 会用整页后备覆盖显示；实际快照和后备都不可用时会显示占位并报告，不能保留互动；
- 隐藏节点不导出，场景背景写入幻灯片背景，不会额外生成一张覆盖全页的静态截图。

PPTX 的定位是提取素材和继续排版，而不是高保真静态归档。实时 Player 的运行时 underlay、Phaser Canvas、组件 DOM/WebGL、运行时 overlay 使用固定平面；导入 PPTX 后这些视觉会变成独立图片并按对象顺序放置，因此混合渲染器的固定平面关系不保证逐像素复现。需要完全固定画面时请导出 PDF；需要保留互动时请导出单 HTML 或网页包。

### 14.5 导出检查建议

- 小中型互动交付可选单 HTML；含大视频、大量声音或其他资源密集内容时优先网页包；打印或固定版式选择 PDF；在 PowerPoint 中继续编辑时选择 PPTX。
- PDF 固定 Player 的静态合成画面；PPTX 中普通节点可继续编辑，互动组件只保留静态快照，场景/全局运行时优先使用实际捕获层并在失败时回退到 `staticFallback`。
- 大量高分辨率图片和视频会增加导出时间、文件体积和内存占用。含大视频时直接优先网页包；单 HTML 出现体积警告时改用网页包，其他导出失败时再压缩素材或删除未使用素材。

## 16. 安全与本地数据边界

- 编辑器 Renderer 没有 Node.js、Electron、任意文件系统或 Shell 权限；文件只能通过系统对话框、当前已批准工程路径或受控的最近工程列表访问。
- 编辑器与预览窗口禁止外部导航、新窗口、下载、设备权限和非白名单网络请求。生产版默认不连接网络。
- 中央统一画布的 authoring / playback Player 文档使用临时 Blob URL，并位于不授予同源权限的 sandbox iframe；工程与组件素材通过可转移二进制缓冲区进入沙箱，再由 iframe 创建同源 Blob URL。主进程仅允许编辑器主窗口中的同源派生 Blob 子框架导航，主框架与独立预览窗口仍拒绝 Blob 和外部导航。编辑器只接受当前会话的 Player 消息；实例替换、关闭或失败时，父窗口撤销文档 URL，iframe 在卸载时撤销素材 URL。authoring 状态还冻结互动、媒体、导航与课程状态写入；这些边界解决实例隔离与状态竞态，但不把可信运行时变成可安全执行的任意第三方脚本。
- `.h5lesson`、最近工程列表和自动恢复副本保存在本机；单 HTML、网页包、PDF、PPTX 仅写入用户在系统对话框中选择的位置。
- 导出的单 HTML 与网页包都限制网络连接，但其中的可信运行时和组件代码仍可控制课件页面自身。
- `.h5lesson` 的自由运行时和 `.h5component` 都是可执行代码，不等同于普通图片素材。格式校验不能证明其业务逻辑可信。

## 17. 常见错误处理

| 提示或现象 | 建议 |
| --- | --- |
| 工程文件损坏 | 重新复制原文件，或从备份/自动恢复副本恢复；不要修改压缩包内容 |
| 工程格式版本不支持 | 使用创建该工程的兼容编辑器版本，或升级当前编辑器 |
| 最近工程无法打开 | 文件可能已移动；使用“打开”重新选择新位置 |
| 自动恢复失败 | 立即手动另存工程，检查磁盘空间和用户目录写权限 |
| 图片类型不支持 | 转为 PNG、JPEG、WebP、GIF 或 SVG |
| 图片读取失败 | 重新导出图片，确认扩展名与内容一致且文件未被占用 |
| 声音或视频无法导入/播放 | 转为标准 MP3/OGG/WAV/M4A 或 MP4/WebM，确认浏览器可解码且文件未损坏 |
| 视频在单 HTML 中启动缓慢 | 改用网页包；大视频不建议以内联 Base64 单文件交付 |
| 组件缺少 manifest/runtime | 联系组件作者重新打包 |
| 组件 manifest 校验失败 | 按组件开发指南修正字段、版本和文件路径 |
| 组件包无法删除 | 先查看组件包管理中的场景/全局实例数并删除所有实例；被引用的包会被安全阻止删除 |
| 组件替换失败 | 必须选择同 ID 且覆盖现有实例作用域的新包；失败不会改写当前工程 |
| 组件运行异常 | 打开“工程检查”，导出诊断报告后交给组件作者；故障实例会被隔离，其他内容应继续运行 |
| 导出被阻断 | 打开“工程检查”，逐项定位并修复“错误”；提醒和建议不阻断 |
| 保存或导出失败 | 检查权限、文件占用和磁盘空间，改存其他目录 |
| 单 HTML 文件过大 | 按提示改用网页包；若继续单 HTML，请在目标电脑实测启动速度和内存占用 |
| 网页包打开空白 | 确认已经完整解压，且 `index.html`、`course-data.js`、`player/`、`assets/` 等目录结构未被破坏 |
| PDF/PPTX 导出慢或失败 | 压缩高分辨率图片、减少场景/素材后重试 |
| 双击入口未打开编辑器 | 确认已安装 Node.js LTS；保留完整源码目录和 `package-lock.json`，查看启动窗口中的构建错误后重试 |

应用会把主进程、编辑器、预览和组件的异常写入轮转的本地诊断日志；界面提示会给出中文原因和处理建议。可从“工程检查”导出文本诊断报告。单个组件异常不会使其他场景停止工作。

## 18. Editor 1.0.0 收敛边界

Editor 1.0.0 不提供通用关键帧/路径时间轴、节点连线式状态机、内置题库/成绩系统、多人协作、云存储、模板市场、组件热重载、移动端编辑、任意网页导入、DOM/Phaser/Three 自动代码转换或视频文件导出。编辑器提供事件驱动的元素入场/退场、顺序/并行步骤、表单式场景/全局交互、声音库和可编辑视频节点；可信运行时和组件负责复杂连续动画与业务互动，Three.js 如需使用只随具体内容打包。

Blueprint、AI 局部 patch 和其他编辑器内 AI 接入统一延后到 2.0 以后。1.x 的统一画布只提供版本化、可校验的 authoring patch 与显式目标边界，不会调用模型、自动理解画面或替用户修改工程；AI 仍可在编辑器外通过规范和可复现脚本生成完整 `.h5lesson`。

仓库中的 `orchestrate-courseware` 仍可用于编辑器外部策划编排；`build-project-v7-courseware` 只对应已归档的 Project V7 原型，不能在当前主干生成可打开工程。面向 Project V8 的实现 Skill 将在 Runtime API 2、Component API 4 与仓库边界完成收敛后替换它；在此之前不要从策划交接进入新课例工程生成。

PDF 和 PPTX 都不保留场景导航、声明式交互、声音、视频播放、自由运行时和组件行为；需要互动时请导出单 HTML 或网页包。统一全局层可直接编辑母版式原生元素、教师控制器和全局组件，但不会把任意运行时代码反向拆成可视化节点；稳定画面应主动创作为场景状态，瞬态效果仍在当前位置试运行中检查。

开发者可使用 [Project V8 五路径渲染宿主过渡基准](../examples/render-host-benchmark/README.md)核对原生节点、Runtime API 2 Phaser、Runtime API 2 DOM + Three.js、Component API 4 DOM 表格与尚待删除的 Component API 3 Phaser 兼容组件。自动化压力段执行 25 轮，合计 100 次定制场景切换和 25 次末页重播，并检查挂载点、Canvas/WebGL、活动 RAF、控制台异常和外部请求。

Editor 1.0.0 收敛分支当前只交付源码启动入口。本轮 Project V8 边界切片已通过类型检查、101 个 Vitest 测试文件共 657 项测试、26 项 Playwright Electron/浏览器端到端测试和桌面生产构建；尚未执行根目录 `启动课件编辑器.cmd` 的人工启动冒烟。Playwright Electron 默认使用透明离屏窗口，不会在桌面或任务栏显示、抢占焦点；需要观察调试时可执行 `npm run test:e2e:visible`。没有生成 1.0.0 Portable、目录版或安装包，历史 1.6.0 二进制不得冒充当前源码版本。自动回归只把当前切片提升到 `engineering candidate`，不等于视觉、教学或正式版结果已经接受。
